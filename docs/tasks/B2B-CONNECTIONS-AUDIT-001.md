# بررسی ارتباطات آژانس‌ها و مشتریان سازمانی

PC-B — 2026-09-11 — `codex/pc-b-b2b-connections-audit`

## نتیجه

تمام ارتباطات عملیاتی هنوز پیاده نشده‌اند. این گزارش وجود کد، اتصال مصرف‌کننده و وضعیت اجرای واقعی را جدا می‌کند. داده آزمایشی مالی یا پورت بدون تولیدکننده، اتصال عملیاتی محسوب نمی‌شود.

مرجع دامنه: PRODUCT_REQUIREMENTS بخش۱۴، MODULE_BOUNDARIES و MODULE_OWNERSHIP؛ ادامه گزارش پوشش PRD و AGENCY-B2B-INTEGRATIONS-001. تصمیم‌های قبلی سقف مستقل هر ارز و تأییدکننده مستقل قرارداد حفظ می‌شوند.

## تغییر اجراشده

- مدیر حساب و تعداد قرارداد فعال دیگر متن ثابت «در دسترس نیست» نیستند؛ از APIهای عمومی دریافت می‌شوند.
- انتخاب شعبه تجاری در فهرست و خلاصه پرونده مشخص است؛ فقط شعب مجاز نشست نمایش داده می‌شوند.
- درخواست‌ها حداکثر برای چهار سازمان همزمان اجرا می‌شوند. پاسخ فیلتر/شعبه قدیمی روی انتخاب جدید اعمال نمی‌شود؛ صفحات قرارداد کامل خوانده و شناسه‌ها یکتا می‌شوند.
- شکست یک منبع، موفقیت منبع دیگر را مخفی نمی‌کند. خطا و نبود مجوز صفر مالی یا صفر قرارداد تلقی نمی‌شوند.
- پیام بالای نمای۳۶۰ دیگر ادعای اتصال واقعی مالی/سفارش ندارد.

## موارد نیازمند قرارداد مالک برای تکمیل

1. **Finance / PC-A:** تولیدکننده `FinancePartyExposurePortV1` با organizationId، branchId، currencyCode، زمان و نسخه معتبر؛ تعریف مبلغ Exposure و بدهی سررسیدشده. سپس register کردن adapter مالک در B2B. آزمون تطبیق ارز، stale-data، مجوز و صورت‌حساب لازم است. نوشتن مستقیم جدول Finance در B2B مجاز نیست.
2. **Sales / PC-A و B2B / PC-B:** قرارداد versioned برای resolve شرایط، تقدم نرخ‌ها، snapshot immutable، reserve/release اعتبار و idempotency. بدون این قرارداد، اعمال خودکار مبلغ روی فروش می‌تواند تعهد مالی نادرست بسازد.
3. **Tasks/Notifications:** رویداد تأیید/انقضا با گیرنده مجاز، deduplication و outbox/زمان‌بندی. گردش محلی تأیید فعلی حفظ شود؛ اعلان عمومی نباید محتوای اعتباری را افشا کند.
4. **HR/IAM:** تبدیل مسئول پیگیری به employee reference و تاریخچه تخصیص، بدون تبدیل خودکار User به Employee. مدل فعلی فقط User است.
5. **Integrations:** تعیین سایت/سامانه مقصد، جهت sync، شناسه مرجع، مجوز و روش احراز هویت؛ سپس adapter رسمی. هیچ ارسال بیرونی یا اعطای دسترسی جدید در این بررسی انجام نشده است.

قفل مرکزی Migration/Sales/Travel متعلق به کار دیگر است؛ این کار مدل، قرارداد مشترک یا API مالی را تغییر نداده است. برای استقرار وب، نسخه مشترک جاری حفظ می‌شود؛ API جاری نیز دست‌نخورده است.

## آزمون

تست‌های هدفمند پوشش می‌دهند: نسخه تأییدشده و بازه معتبر، قرارداد منقضی/پیش‌نویس، صفحه دوم و یکتایی، نقش مشتری سازمانی، شعبه، نبود مجوز، لغو درخواست و شکست جزئی. نتیجه اجرای بررسی‌ها و QA زنده در PROJECT_STATUS ثبت می‌شود.
