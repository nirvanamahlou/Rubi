## Delivered contracts

- POST search/report are branch-authorized, private/no-store; private search text is in the body, never URL. Contacts have bounded summaries only; calls and notes use separate keyset history endpoints (default20, maximum50). Legacy list is now bounded to one latest call and counts; API and Web must be released together.
- Stable ordering is latest occurredAt descending, contact UUID ascending. Page revision includes call/request/task changes, current team membership and due-date boundaries. Changed pages return409 and require explicit refresh. Selection stays independent of refreshed rows. This is consistency detection, not a historical snapshot or live telephony stream.
- Exact normalized phone uses the existing keyed fingerprint. Persian/Arabic letters, digits, marks and whitespace normalize before branch-domain HMAC whole-word indexing. Name/subject search is AND of whole words, maximum12; substring search is intentionally unavailable. No plaintext shadow, per-query whole-database decryption or private browser storage. Equality/frequency/token-count leakage is documented in DECISIONS; rotation requires full index rebuild. Incomplete backfill refuses search/report, rather than silently omitting records.
- Filters: date interval, latest/history meaning, direction, result including unknown, current team, registering agent, historical recorded unit, source, request status, action state/deadline, permitted branch, manual/telephony/unknown origin and incomplete fields. The operator explicitly links the existing request.customerId FK; multiple requests can identify different people sharing a number, and different phone groups can link the same customer. Association changes are audited with actor/time and old/new IDs. No automatic Contact/Customer/Passenger merge.
- Existing Customer Affairs referral records are reused for Sales/Support, with actual authorized recipient, request FK, version validation, command replay and open-duplicate guard. No Sales contract, booking, financial amount or sales conversion is created implicitly. Native Customers permission is additional to Call Center permission; no new operational grants were applied.
- Request/action loading is separate from the contact list: requests10/page, actions20 per request/page; existing encrypted revision cap200 is retained. Calls/notes are independently cursor-paged. Very large request revision payloads remain capped rather than a new unlimited event stream.

## Reports and UI semantics

Reports are server-side over authorized data, not visible table pages. Calls/contacts/sources/registrations follow call filters across all matching historical calls; latest/history selector is explicitly list-only. Requests created within the interval and current branch action backlog are separately labelled branch-wide sections; completion uses completedAt. Unique contact means branch phone-group, not unique person; anonymous calls remain separate. Completed actions are the denominator of on-time completion; no completed actions means unknown/null. Current responsibility and historical completion actor are distinct. Source unknown group is retained. No invented waiting time, duration, answer rate or conversion KPI; export is not implemented.

Loading, empty results, retry, stale/offline indication, access denial, selected row, pending note draft preservation, success feedback and explicit refresh are implemented. Shared dropdowns/date pickers, keyboard navigation, dialog Escape and return focus preserve ERP patterns. Drafts remain memory-only. No Issabel API is available, so incoming-call realtime routing and recordings ingestion are not represented as delivered.
