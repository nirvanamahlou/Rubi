## Domain and compatibility

Accounting owns AccountingCompanyScope, an adapter over LegalEntitiesService.current/selectable. Other modules' issuer selection is unchanged. JAHAN_ACADEMIA resolves to JAHAN_BASTAN for accounting only; three root companies have one ledger each. A nullable restrictive FK from AccountingBook to LegalEntity and a unique company index preserve existing ledger IDs, branch permissions, currencies and all dependent records. Existing unbound ledgers are never assigned by guessed title or branch. Aggregate administrators can inspect them in the ledger list; explicitly open one, select the correct company in the header and save its metadata to bind that same ledger. Commands on an unbound ledger require that explicit binding first. A company already having a ledger cannot acquire another by adoption or concurrent creation.

Both creation and metadata saving derive title from the authoritative company and require the submitted company ID to match the active header context. Branch permissions remain enforced independently. New ledgers retain the existing IRR default and an authorized internal branch; the branch and base-currency controls are removed from the UI. Existing ledger currencies are not changed. Aggregate mode is read-only; select a concrete company to write. The central book lookup scopes snapshots, documents, reports and commands; the workspace, KPI and mapping query caches include header selection. Snapshot loading completes before mounting the editor, so an existing ledger is not mistaken for an empty creation form. The ledger list remains available even with no ledger yet.

The ledger's allocation + can create a fiscal-year configuration and assignment atomically, or choose an existing active fiscal year. Year number is 1–9999; title and both ISO dates are required. Existing duplicate allocation, overlapping date range, command replay, optimistic version, closed/used-period and journal guards are preserved. Date picking uses the established application calendar and canonical date format. Failed allocation rolls back a newly created fiscal-year record. Financial amounts and journal posting semantics are unchanged.
