- انتخاب‌گر مشترک فرم درخواست و تیکت، پیش از جست‌وجو پنج مشتری/مسافر فعال و قابل‌دسترسی را نشان می‌دهد؛ جست‌وجو، صفحه‌بندی و لینک پروندهٔ اصلی باقی مانده‌اند. چون API حداقل ۱۰ رکورد در هر درخواست می‌پذیرد، هر دو صفحهٔ پنج‌تایی رابط از یک صفحهٔ ۱۰تایی API بدون افتادن یا تکرار رکورد نگاشت می‌شوند.

- اگر پروندهٔ اصلی ایجاد شود ولی ثبت اطلاعات جانبی شکست بخورد، فرم پروندهٔ ایجادشده را آشکار می‌کند و ارسال تکراری را می‌بندد. اگر پاسخ POST نامطمئن باشد، ارسال دوباره تا زمان بستن فرم بسته و کاربر به بررسی فهرست هدایت می‌شود.

## ریسک باقی‌مانده

API ایجاد Customers کلید idempotency ندارد. در قطع پاسخ پس از commit، فرم فعلی جلوی ارسال دوباره را می‌گیرد؛ اما پس از بستن و بازکردن دوباره یا در تب/دستگاه دیگر تضمین سراسری وجود ندارد. افزودن idempotency سمت API باید به‌عنوان کار جداگانه با مالک Customers و قرارداد سازگار هماهنگ شود؛ این PR قرارداد Backend را تغییر نمی‌دهد.
