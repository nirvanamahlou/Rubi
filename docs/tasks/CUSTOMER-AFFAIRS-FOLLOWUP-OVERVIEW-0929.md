# پیگیری ردیفی و درخواست‌های اخیر در نمای کلی

- تاریخ: 2026-09-29؛ `COMPUTER_ID=PC-B`؛ شاخه `codex/pc-b-ca-followup-overview-0929` از `origin/develop@bb4209e0`.
- علت: نمای کلی فقط درخواست‌های مرحلهٔ `HANDOFF_PROPOSED` را در کارت درخواست‌ها می‌خواند؛ درخواست تازه با مرحلهٔ `NEW` در آن دیده نمی‌شد. شمارندهٔ درخواست‌های باز در Backend از قبل `NEW` را لحاظ می‌کرد.
- تغییر: پنل جداگانهٔ «آخرین درخواست‌ها» پنج رکورد آخر را بدون فیلتر مرحله از API فهرستِ محدود به دسترسی/شعبه می‌گیرد. پنل‌های «منتظر پذیرش فروش» و «نیازمند پیگیری» با فیلترهای قبلی می‌مانند. فهرست درخواست‌ها ستون و دکمهٔ مشخص «پیگیری» دارد؛ شناسهٔ همان ردیف به `view=leads&lead=<id>` رمزگذاری و به نمای پروفایل فرستاده می‌شود. دکمه‌ها برچسب قابل‌تمایز برای صفحه‌خوان دارند.
- منظور «آخرین» در این نسخه، ترتیب فعلی API بر پایهٔ `updatedAt` است؛ رکورد تازه‌ثبت‌شده بلافاصله در صدر قرار می‌گیرد، اما پنل تاریخچهٔ مطلق ایجاد نیست.
- اعتبارسنجی: چهار فایل تست متمرکز Web، ۲۸/۲۸ موفق؛ شامل جدایی سه query نمای کلی، حالت بدون مجوز/خالی و مسیر شناسهٔ هر ردیف. Web typecheck، ESLint محدود، production build و `git diff --check` موفق. هیچ API/قرارداد، Migration، Permission، دادهٔ عملیاتی یا runtime ۳۱۰۰ تغییر نکرد.
- باقی‌مانده: CI و بررسی نسخهٔ فعال پس از review/ادغام.
