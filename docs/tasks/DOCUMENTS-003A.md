# DOCUMENTS-003A — کاربردپذیری، لینک داخلی و اسکن امن لوکال

تاریخ: 2026-08-31

مالک اجرا: `PC-B`

شاخه: `codex/pc-b-documents-usability`

والد: `codex/pc-b-documents-vertical-slice@37558aa`

تحویل: Draft PR #65

## هدف و محدوده

این Slice تجربه استفاده از Documents را روی Vertical Slice موجود کامل می‌کند:

- حذف نمای مستقل «فعالیت و گزارش دسترسی» و نگه‌داشتن Timeline فقط در جزئیات همان فایل؛
- تکمیل اشتراک‌گذاری با لینک داخلی مستقیم، احراز‌شده و Permission-aware؛
- فعال‌کردن نماهای «اسناد من»، «بارگذاری‌های من»، «اخیراً دیده‌شده» و «علاقه‌مندی‌ها»؛
- بهبود رنگ، عمق، Hover/Active state و خوانایی تمام بخش‌ها و منوی داخلی؛
- اتصال اسکن واقعی Microsoft Defender در محیط لوکال PC-B بدون جعل وضعیت `CLEAN`.

این کار هیچ Prisma Schema، Migration، Seed عمومی، Dependency یا Lockfile را تغییر
نمی‌دهد. تولید و صدور سند همچنان در ماژول مالک باقی می‌ماند.

## رفتار نهایی

### فعالیت و گزارش دسترسی

ورودی مستقل از منوی Documents حذف شد. رویدادهای مشاهده، دانلود، بارگذاری و اسکن در
تب «فعالیت و نگهداری» جزئیات هر سند قابل مشاهده‌اند؛ بنابراین گزارش از زمینه فایل جدا
نمی‌شود.

### اشتراک‌گذاری

برای هر سند لینک داخلی با قالب `/documents?document=<id>` ساخته می‌شود. لینک هم در
بخش «اشتراک‌گذاری‌ها» و هم در تب دسترسی همان فایل قابل مشاهده و کپی است. بازکردن لینک
مستقیماً جزئیات سند را نمایش می‌دهد، ولی گیرنده باید وارد سامانه شده و مجوز همان سند را
داشته باشد. این Slice لینک عمومی/ناشناس یا دانلود بدون کنترل امنیتی ایجاد نمی‌کند.

### نماهای شخصی

- «اسناد من» بر اساس مالک ثبت‌شده و کاربر احراز‌شده از Backend فیلتر می‌شود.
- «بارگذاری‌های من» بر اساس ایجادکننده نسخه/سند و کاربر احراز‌شده فیلتر می‌شود.
- «اخیراً دیده‌شده» از Audit موفق `documents.metadata.view` همان کاربر استخراج می‌شود.
- «علاقه‌مندی‌ها» شناسه سند را به تفکیک کاربر در مرورگر نگه می‌دارد؛ محتوای فایل یا
  داده محرمانه در مرورگر ذخیره نمی‌شود و نمایش نهایی همچنان از API مجاز عبور می‌کند.

### اسکن امنیتی

Adapter لوکال Microsoft Defender فایل رمزگشایی‌شده را فقط در یک فایل موقت خصوصی
اسکن می‌کند و آن را پس از اجرا حذف می‌کند. قبل از اسکن، SHA-256 فایل با نسخه ثبت‌شده
تطبیق داده می‌شود. فقط Exit Code پاک Defender وضعیت `CLEAN` و آزادسازی قرنطینه را
ایجاد می‌کند؛ آلودگی، خطا، نبود موتور یا عدم تطابق Hash همگی fail-closed هستند.

صف موجود با Claim، شمارش تلاش، retry محدود و نتیجه نهایی پردازش می‌شود. روی دیتابیس
لوکال، هر ۶ فایل آزمایشی موجود واقعاً اسکن شدند: ۶ `CLEAN`، شش Job `COMPLETED` و شش
قرنطینه `RELEASED` با دلیل `ANTIVIRUS_SCAN_CLEAN`. پیش از اجرا Backup خصوصی معتبر
در مسیر خارج Git تهیه شد.

## رابط کاربری

- منوی داخلی از «نمای کلی» تا انتها پس‌زمینه آبی روشن و Active state آبی واضح دارد.
- کارت‌های KPI، تازه‌های آرشیو، جدول‌ها، فیلترها، اشتراک‌گذاری و جزئیات فایل با رنگ،
  سایه، Hover و مرزبندی هماهنگ بازطراحی شدند.
- پیام قدیمی «Antivirus production متصل نیست» در محیطی که Defender فعال است حذف شد؛
  فرم بارگذاری وضعیت واقعی «اسکن امنیتی فعال» و دکمه «بارگذاری و اسکن امن» را نشان
  می‌دهد.
- متن فنی و Placeholderهای Slice از نمای اصلی حذف شدند و دکمه بازگشت در بخش‌های داخلی
  باقی ماند.

## اعتبارسنجی

- API: lint، typecheck و build موفق؛ ۷۰۲ تست موفق و ۶۶ تست اختیاری skip.
- Web: lint، typecheck و production build موفق؛ ۵۱۵ تست موفق.
- Contracts: lint، typecheck و build موفق؛ ۱۷ تست موفق.
- مرورگر احراز‌شده با کاربر Nirvana: منوی رنگی، نبود نمای مستقل Activity، اسناد من،
  اخیراً دیده‌شده، افزودن/نمایش علاقه‌مندی، لینک‌های قابل کپی، بازشدن مستقیم جزئیات،
  Timeline داخل فایل و نمایش نتیجه پاک اسکن همگی کنترل شدند.
- سلامت API روی `http://localhost:4000/api/v1/health` و رابط روی
  `http://localhost:3100/documents` تأیید شد.

## محدودیت‌های باقی‌مانده

`DOCUMENTS-003` برای Object Storage تولیدی S3/MinIO، Worker توزیع‌شده، monitoring و
recovery باز می‌ماند. `DOCUMENTS-004` نیز برای لینک عمومی/زمان‌دار، سیاست ابطال، Export،
retention نهایی و اتصال producerها باز است. فرض ظرفیت فعلی همان سند
`DOCUMENTS-002` است: کمتر از ۱۰۰ درخواست بر ثانیه، p95 متادیتا حداکثر ۵۰۰ms، SLO
برابر 99.9%، RPO برابر ۱۵ دقیقه و RTO برابر ۴ ساعت؛ مقادیر تولیدی نیازمند تصمیم عملیات
هستند.
