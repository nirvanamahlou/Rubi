## Delivery and boundaries

- HR payroll opens a table of actual active, scoped HR employees, linked-user indication, personnel code, branch, exact salary amount, currency, period and payment date. A person must have an HR employee identity; an IAM account alone is not an employment/payroll record. Submission requires hr.manage, hr.approve and hr.sensitive; the existing HR command owns approval and immutable amount-only payroll.paymentRequests. No fabricated gross salary, deductions, payslip or employee bank details.
- HR producer HrPayrollFinancePublicService publishes only approved record/version, employee ID/name snapshot, branch, period, amount/currency and due instant. Finance never queries private HR tables. Finance-owned cases deduplicate HR source and employee-period. A returned, unpaid case may receive a new approved HR input from its original requester; old HR and Finance history remain immutable.
- Finance operational requests cover approved payroll and manual REFUND/COMMISSION/CHECK/ADJUSTMENT. Refunds require an exact confirmed public Sales receipt in the same branch/currency, and a transaction advisory lock limits total non-rejected refund requests to the receipt principal. This is recorded operational payment, not automatic commission calculation, legal accounting, bank transfer, cheque issuance/clearance or Sayad registration.
- NEW -> UNDER_REVIEW -> APPROVED -> PAYING -> PAID. Return/reject/resubmit require a reason. Commands use operation UUID, actor/payload fingerprint, optimistic version CAS and append-only revisions. Decimal(24,4), currency and real restrictive FKs are retained; positive payment cannot exceed remaining. Account validation is branch/currency scoped; Master Data's public producer validates an active outgoing payment method in the payment transaction and its authorized label is stored in the Finance revision snapshot.
- Optional document linkage uses the Documents public authorized detail and requires an active, complete, CLEAN current version. Attachment access remains governed by Documents. Request, beneficiary, source/reference, description and decision timeline stay visible with the case.
- Server filtering covers source/status/open-closed, authorized branch, normalized person/search, exact amount, currency, creation and due dates; stable paging displays 25 rows. Private named views belong to their creator, revalidate branch access and are limited to 20.
- Branch reminder administration requires finance.account.manage plus finance.read. Selected manager must be active with finance.read in that active branch. Worker revalidates live IAM access and current policy, sends generic no-money/no-person notification at 24 hours before due and escalates at 24 hours after; it skips closed cases and deduplicates each source/deadline/manager/phase transactionally. Native source deadlines are supported through their public inbox projections; no invented operational FK.

## Excel, PDF and receipts

New permissions finance.export and finance.request.manage are catalog entries only: there is no silent role grant. Administrator must assign them explicitly using current role administration. Export additionally requires finance.read and always applies branch/source owner authorization server-side.

XLSX is genuine OOXML with right-to-left presentation, freeze/filter/print settings and literal untrusted text (no formula evaluation/external links). Exact decimal values beyond Excel's 15 significant digits are stored as text, never rounded silently. Currency totals stay separate; opposite payment/receipt directions are never summed as one balance.

Exports include all filtered queue rows, not just the visible page. Limit is 2000, with explicit rejection rather than truncation. Queue export rejects unavailable sources and explicitly discloses bounded current Procurement projections; it is not a complete historical ledger. History export walks authorized persisted cursor pages and detects repeat pages/records. A receipt requires exact source + recorded transaction ID and one authorized persisted transaction. Historical partial-payment totals reflect that payment's time, not a fabricated present balance. Internal receipt is not bank confirmation.

PDF comes from a server-authorized snapshot, trusted embedded Vazirmatn font, escaped text, A4/RTL layout and receipt signatures. Renderer uses existing Chrome/Edge, no new dependency, no arbitrary client HTML/URLs, private temporary profile and isolated environment, timeout/concurrency caps and cleanup. Use an absolute FINANCE_PDF_CHROME_PATH on servers without a detected browser (SALES_PDF_CHROME_PATH is a fallback). Missing browser returns 503, not a fake PDF. Download checks MIME and binary signature and refreshes an expired session once. Responses are private/no-store/nosniff.
