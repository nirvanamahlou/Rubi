## Permission matrix (proposal, not IAM grants)

All actions require the exact permission AND assigned branch. A branch other than the
active branch additionally requires `hr.scope.multibranch`; this never grants an
unassigned branch. Legal Entity context does not alter the employee scope.

| Scope | Allowed ceiling, still requiring explicit grants |
| --- | --- |
| SELF | Own `hr.read`, `hr.leave.request`, `hr.documents.read` only |
| MANAGER | Explicit managed employee IDs only: read, contract.read, attendance.read, leave.approve, performance.read/manage, documents.read; never self approval |
| HR | Explicitly granted requested HR permissions within assigned branch scope |
| Missing actor/grant/scope | Denied |

The full 28 functional permissions plus `hr.scope.multibranch` are declared in
`apps/api/src/hr/hr.policy.ts`. Sensitive reveal additionally requires a valid purpose,
10–500 character reason and successful audit before a field read. Only the purpose code,
field, actor, subject, UTC and trace ID enter audit; free text/value do not. Read projections
exclude private monetary, assessment and document fields. Documents access requires matching
stable ID, authorization and CLEAN status; the public adapter must recheck/audit on open.
Legal hold always prevents disposal; no approved retention policy also denies disposal.
Contract activation and review finalization require a distinct maker/checker. Leave decisions
also reject a second account mapped to the requesting employee.
