## Implementation delivered

- Product HR routes use the authenticated HR API; the prior preview component remains isolated as a legacy regression fixture and is never imported by the live workspace. No browser session rows are silently copied into shared storage.
- Additive `HrEmployee`, `HrRecord`, command deduplication, audit, leave ledger, attendance-period and notification tables; stable employee/parent/document references, server UTC dates, exact Decimal money with currency, version checks and audited soft deletion. Finalized records require cancellation/corrective workflows instead of rewriting history.
- Organizational companies نیایش سیر / جهان باستان are HR-owned branch records linked to employees; the existing IAM HQ remains the access-control scope. IAM organizations are not relabeled or cloned. Parent links and dependent records are preserved.
- Effective-dated onboarding/promotion/transfer/separation, automatic assignments, leave grants/consumption/cancellation, Tehran clock conversion, attendance exceptions, corrections and closed periods use transactional commands. Date ranges and approved state changes are validated server-side.
- Canonical request inbox references the original operation; bell notifications are durable per-user reads and open the affected record. Sensitive reads and mutations have audit events.
- Contract approval and recorded signed-copy state are distinct. `SIGNED → ACTIVE → ENDED` uses a valid public Documents reference, versions, dates, permissions and reasons. This records an uploaded signed copy, not a cryptographic-signature service. Same-type overlap is rejected; NDA and employment contracts may coexist.
- Consolidated groups: time (work/shifts/leaves/settings), contracts (cases/settings), recruitment (planning/openings/candidates), lifecycle (onboarding/job changes/exit), development (appraisal/training), missions with linked expenses, payroll with finance results/settings, organization, equipment/vehicles. Eight employee-profile groups consume employee UUID links. Related case records open inside the parent dialog.
- Contextual forms, employee photo/attachments through public Documents API, stored filters, aligned controls, branch/date/status/search filters, paginated operation lists, read-only shift calendar and current-data dashboard. Searchable branded PDF and Excel export use authorized filtered rows; import previews row errors and duplicates and invokes the same command preparation as forms.
- HR UI is split into independently loaded modules. `infrastructure/scripts/start-hr-local.ps1 -Build` validates process ownership, builds this checkout, runs web/API on 3100/4000 and verifies a served build fingerprint plus API health. Stale cookies no longer trap the login route. `/human-resources` redirects to `/hr`.

## External dependencies and limits

- Finance settlement approval, payroll calculation/payment delivery, biometric synchronization and job-board ingestion have no usable public producer adapter in this baseline. HR reports these as unavailable and never manufactures payment, settlement or synchronization outcomes. Jobinja/Jobvision remain source links and candidate source metadata, not automated integrations.
- Public Documents currently exposes only `HR_DOCUMENT` for HR, with required expiry. New resumes/photos therefore request archive validity; a dedicated no-expiry type must be added by the Documents owner. File preview continues to respect the owner's scan and authorization policy.
- Leave ledger years are Gregorian in this API. Local selection/display is Persian; statutory calendars, entitlement rules and payroll rules remain organization policy.
- HR bootstrap is scoped and bounded, operation lists are server-paginated, and audit view presents the latest 200 events. This validation is local functional QA, not a production capacity/SLA claim.
