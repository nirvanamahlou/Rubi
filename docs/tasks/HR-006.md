# HR-006 — Rubi HR experience redesign

PC-B / `codex/pc-b-hr-rubi-redesign` / baseline `cfd6549`.

## Scope and acceptance

Use Rubi's existing shared UI and semantic theme tokens throughout the live HR workspace: directory, overview, employees, organization, operation tables, filters, employee dossier, dialogs, inbox and reporting. Keep the existing fourteen home destinations and all consolidated subgroup IDs; do not add sections. Preserve actual data, authorization, existing CRUD/workflow commands, XLSX/PDF, Documents uploads and Persian calendars.

Provide clear page hierarchy, direct navigation among existing sections, consistently aligned range/actions/filters, readable status and row actions, useful loading/empty/error states, and dialogs with reachable submit controls. Retain the owner-approved Master Data card design. Remove duplicated active-page styling and avoid loading detailed screens on the directory route.

## Design and performance assumptions

- Primary device: desktop on a corporate network, with responsive support down to 390px. Existing Next.js authenticated app; no public SEO requirement or framework change.
- Design source: shared Rubi Card, Button, form controls, dialogs, DatePicker, Vazirmatn and light/dark CSS tokens. Accessibility target WCAG AA for changed interactions; PC-B owns verification.
- Targets for future representative p75 measurements: LCP ≤2500ms, INP ≤200ms, CLS ≤0.1. HR-specific route code budget ≤80KB gzip excluding the existing shared Next/Rubi shell. Lighthouse targets accessibility ≥95 and performance ≥90. These are design targets, not production performance claims; report measured local results and gaps separately.
- Existing lazy-loaded screens and exports stay deferred. This change does not introduce a dependency or alter network/API semantics.

## Delivered design

- Kept the fourteen current destinations, subgroup IDs, legacy redirects and all existing data/workflow contracts. The home cards retain the Master Data pattern; a compact selector connects the existing sections directly.
- Replaced fixed-color operation UI with shared Rubi Card/Button and semantic light/dark tokens. Range/actions and filters align, tables have readable status badges and scoped row menus, and employee dossiers and forms share the same visual hierarchy. Wide tables/calendar grids scroll within their panels on small screens.
- Restyled the organization tree/edges and shift calendar. Contextual form dates no longer receive a second input border; submit/cancel controls remain reachable while a long form scrolls. Photo upload is a disclosure within the employee profile.
- Notifications use the same theme, open near the bell, constrain their height and scroll internally. Escape returns focus to the bell. The current endpoint/mark-read behavior is preserved.
- Prevented old source rows appearing under a newly selected operation tab. Dashboard loading/error states no longer report zero requests before data arrives, and overview export waits for the actual report.

## Loading and rendering

Pure record-to-navigation and report-text helpers no longer import the detailed operation/report screens. Employee creation and spreadsheet import are deferred; reports only filter/render their tables when expanded and paginate visible rows. Persian date conversions have a bounded cache, and the shift calendar normalizes record ranges once rather than rescanning date conversions per cell. No package, API, schema, migration or shared shell/component change.
