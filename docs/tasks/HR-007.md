# HR-007 — Current HR on local port 3100

PC-B / `codex/pc-b-hr3100-current` / current application baseline `30d67ec`.

The owner requires the current HR implementation on port 3100. The previous HR preview (`b9b525d`, ports 3188/4188) predates the integrated application's company header, Profile, global Notifications and Documents step-up. Replacing the running application with that old checkout would remove those changes.

## Implementation

- Applied the existing HR-005/HR-006 delta in a separate worktree on current develop. Kept the same fourteen HR destinations and their live workflows, forms, employee dossier, reports, imports, permissions and Persian calendars.
- Retained the current four-company contracts/header, Profile, IAM/MFA, Documents, B2B, Marketing and Master Data. HR registration, permission catalog v8 and Prisma relations are additive; existing contracts and non-HR migrations remain intact. Maintenance/test constructors use the current public IAM/Documents dependencies.
- The common bell now consumes pending HR notices through the public HR client alongside its existing feeds. Acknowledging an HR notice persists through its existing endpoint; its history stays in HR audit. The former HR click listener is no longer mounted, and HR commands are excluded from duplicate browser notices.
- Local API URLs retain their configured port and follow the local web hostname, so `localhost` and `127.0.0.1` use matching host-scoped cookies. Remote API URLs are unchanged.
- The legacy `/human-resources` URL redirects in Proxy before mounting an authenticated shell, retaining its query parameters and the destination's normal login check. This avoids an intermediate page rotating the session while redirecting.
- Existing header controls use two rows on small screens after browser QA found a 14px overflow at 390px. Desktop layout and all controls/branding remain present.

## Data and runtime isolation

Task «PC-B Uniting» handed over only the web listener on 3100. Its checkout, API4000 and database `rubi_local_integrated_20260908` are preserved. The original HR checkout/database are also unchanged.

A fresh PostgreSQL dump was taken from the integrated database and restored as `rubi_hr_current_20260908` on local port 55432. Existing employees, records, amounts and leave ledgers match the original HR database; the original has 33 additional read-only QA audit entries, which remain there. The clone retains six employees, 115 HR records and four active legal entities. Document storage was copied to a separate directory with the original encryption key reused from its protected environment file. No real user password or business data was reset.

All 35 existing migrations are present and Prisma reports the clone is up to date. The two HR migrations were already applied in the source snapshot; no new database migration was run for this local delivery. PostgreSQL tests use separate randomly named disposable databases.

The ignored web `.env.local` sets `NEXT_PUBLIC_API_BASE_URL=http://localhost:4190/api/v1`. API4190 uses the dedicated database and document snapshot. The launcher now accepts the API port, protected environment-file path, database name and document-storage directory, verifies the web fingerprint/commit, and refuses to stop a listener belonging to another checkout.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File infrastructure/scripts/start-hr-local.ps1 -Build -Port 3100 -ApiPort 4190 -ApiEnvFile C:/Users/admin/Rubi-hr-foundation/apps/api/.env -DatabaseName rubi_hr_current_20260908 -DocumentStorageRoot C:/Users/admin/AppData/Local/Rubi/hr007-documents
```
