# دسترسی کاربران به یکپارچه‌سازی‌ها — ۲۰۲۶-۱۰-۲۱

COMPUTER_ID=PC-D؛ اجرای محدود با واگذاری صریح مالک محصول. مالکیت IAM و سایر ماژول‌ها تغییر نکرده است.

## محدوده بررسی و تغییر

ساختار API/Web/Contracts/Database، اسناد معماری، مرز ماژول‌ها، گردش سفر، مدل داده، امنیت، وضعیت و تخصیص کار و مسیر مؤثر احراز هویت، واگذاری دسترسی و تنظیمات بررسی شدند. این گزارش ادعای بازبینی خط‌به‌خط تمام کدهای نامرتبط پروژه نیست. تغییر فقط در کاتالوگ دسترسی IAM، مصرف‌کننده مدیریت کاربران و مجری یکپارچه‌سازی انجام شده است.

شاخه `codex/pc-d-integrations-user-permissions-1021` از `origin/PC-D-Integration` ساخته و برای حفظ پیاده‌سازی تحویل‌شده به پیش‌نیاز موجود `e59988e8` fast-forward شد. مبنای برنامه همان `develop@c5b267c4` است؛ قابلیت‌های جدیدتر develop وارد این واحد نشده‌اند. پیش از PR آینده، اختلاف مبنا و مقصد باید دوباره بررسی شود.

## روش تنظیم برای هر کاربر

مدیریت سیستم ← مدیریت کاربران ← انتخاب کاربر ← دسترسی‌های دستی ← یکپارچه‌سازی‌ها.

ابتدا تیک صفحه اصلی یکپارچه‌سازی و سپس بخش‌های لازم انتخاب و ذخیره شود:

| تیک | کاربرد |
| --- | --- |
| برندها و سامانه‌ها | دیدن فهرست و مشخصات عمومی سایت‌ها |
| نمای کلی | دیدن خلاصه وضعیت فهرست |
| اتصال‌ها و تأمین‌کنندگان | دیدن برنامه اتصال، مشخصات غیرمحرمانه و adapterهای موجود |
| رویدادها و وب‌هوک‌ها | دسترسی به صفحه وضعیت این مسیر |
| نگاشت و گردش داده | دسترسی به صفحه نگاشت |
| همگام‌سازی‌ها | دسترسی به صفحه وضعیت همگام‌سازی |
| سلامت و خطاها | دسترسی به صفحه پایش |
| لاگ‌ها و سوابق | دیدن سابقه تغییر تنظیمات مجاز |
| تنظیمات اتصال و دسترسی | دیدن قابلیت‌ها و تنظیمات یکپارچه‌سازی |

صفحه‌های آماده‌نشده همچنان وضعیت واقعی «تنظیم نشده/داده موجود نیست» دارند؛ تیک دسترسی به معنی عملیاتی‌شدن اتصال نیست.

برای ایجاد فهرست، افزودن/ویرایش سایت، قابلیت یا آرشیو غیرمخرب، تیک تنظیمات اتصال و دسترسی، عملیات موجود `system.settings.manage` و فیلد `field.system-settings.integrations.registry` لازم‌اند. کنترل موجود `system.module.integrations` دوباره ساخته نشده و همان تیک تنظیمات است. تیک مشاهده به‌تنهایی اجازه نوشتن نمی‌دهد. مجوز عمومی تنظیمات قدیمی حفظ شده؛ به‌تنهایی سایر صفحه‌ها یا فیلدهای تنظیمات را در پروفایل دستی باز نمی‌کند. تنظیمات شعبه کاربر همچنان جداگانه در IAM تعیین می‌شوند.

## اجرای سمت سرور و سازگاری

- هویت و دسترسی از IAM موجود مصرف می‌شود؛ هیچ نقش، کاربر یا datastore موازی ایجاد نشده است.
- صفحه‌های جدید پروفایل‌های دستی پیش‌فرض بسته‌اند و انتخاب صریح مدیر لازم است. هیچ دسترسی جدیدی روی حساب‌های موجود نوشته نشده است.
- پروفایل‌های قدیمی غیر‌دستی از تصمیم قبلی صفحه اصلی ارث می‌برند؛ منع صریح هر بخش رعایت می‌شود.
- تولیدکننده کاتالوگ IAM و مصرف‌کنندگان مدیریت کاربران، API و منوی Web از شناسه‌های یکسان استفاده می‌کنند. قرارداد خواندن v1 یک پارامتر اختیاری `section` دارد؛ کلاینت قدیمی بدون آن فقط با داشتن دسترسی حداقل یک بخش مجاز است.
- API بخش غیرمجاز را با 403، selector ناشناخته را با 400 و شعبه غیرمجاز را پیش از خواندن داده رد می‌کند. درخواست adapterها به تیک اتصال نیاز دارد.
- فهرست و شمارنده‌های عمومی، داده مشترک صفحه‌ها هستند. مشخصات setup تنها برای اتصال/تنظیمات و `lastChange` فقط برای سوابق برگردانده می‌شوند؛ پنهان‌کردن منو تنها کنترل امنیتی نیست.
- کنترل هم‌زمانی نسخه، عدم حذف شناسه‌ها، ثبت audit و قرارداد عمومی SystemManagement موجود حفظ شده‌اند.
- حق واگذاری مدیر غیرسیستمی همچنان به مجوزهای قابل واگذاری خودش محدود است. انتخاب کل بخش به IAM یا تنظیمات سایر ماژول‌ها تیک نمی‌زند.

## خارج از این تغییر

ورود اختصاصی به پنل نیایش سیر، اتصال حساب ERP به حساب سایت، نقش اختصاصی هر سایت و قطع نشست خارجی هنوز به قرارداد و پیاده‌سازی SSO در دو طرف نیاز دارند. این واحد هیچ ورود خارجی، credential، انتشار تور/بلیت، sync یا موفقیت اتصال ساختگی اضافه نمی‌کند. مجوز صفحه یکپارچه‌سازی جایگزین مجوز عملیات فروش، رزرواسیون یا مالی نیست.

Schema، Migration، Seed، Dependency/Lockfile، تنظیمات Docker و داده کاربران تغییر نکرده‌اند. انتشار GitHub و جایگزینی runtime در این واحد انجام نشده است.

## اعتبارسنجی

۱۱۹ تست هدفمند موفق‌اند: ۱۳ قرارداد، ۳۵ رابط یکپارچه‌سازی/مدیریت کاربران، ۶۲ API/IAM و ۹ ترجمه. ESLint محدوده، typecheck قرارداد/API/Web، build تولیدی API/Web با ۶۵ مسیر، همگام‌سازی ترجمه و format موفق‌اند. خروجی قدیمی Prisma از Schema موجود با URL نمونه بدون اتصال به دیتابیس بازتولید شد؛ Migration یا تغییر داده انجام نشد. آزمون تعاملی مرورگر روی runtime به‌روزشده در محدوده این واحد نیست؛ پوشش UI از تست render و مسیر ذخیره موجود انجام می‌شود.
