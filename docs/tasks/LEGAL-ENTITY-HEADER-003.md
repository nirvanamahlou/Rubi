# LEGAL-ENTITY-HEADER-003 — چهار شرکت با رنگ مستقل

## محدوده مشترک PC-A و PC-B

طبق درخواست صریح مالک در 2026-09-08، هر دو کامپیوتر مجاز به اجرا و توسعه انتخاب شرکت
و رنگ Header هستند. این مجوز به معنی ایجاد حساب `pca` یا `pcb`، تغییر Role/Permission
یا اجازه ویرایش هم‌زمان یک فایل نیست. هر کار بعدی Branch و رزرو فایل مشخص خود را دارد.
قرارداد عمومی `legal-entities.v3` برای هر دو مصرف‌کننده یکسان است.

| شرکت | کد عمومی | رنگ Header |
| --- | --- | --- |
| نیایش سیر سحر | `NIYAYESH_SEIR_SAHAR` | آبی |
| جهان باستان | `JAHAN_BASTAN` | سورمه‌ای |
| قسطی رو | `GHESATI_RO` | سبز |
| جهان آکادمیا | `JAHAN_ACADEMIA` | بنفش |

فهرست شرکت‌ها همچنان از API احرازشده و رکورد فعال واقعی می‌آید؛ هیچ گزینه ساختگی در
مرورگر افزوده نمی‌شود. لوگوهای موجود حفظ می‌شوند و رنگ فقط Header را تغییر می‌دهد.
حالت تجمیعی مدیران ظاهر خنثی قبلی را حفظ می‌کند. فایل App Shell و تغییرهای HR/Profile
در PR #99 بازنویسی نمی‌شوند.

## آماده‌سازی روی هر دو کامپیوتر

Git کد را منتقل می‌کند، نه دیتابیس یا Secret را. Seed مشترک فعلی فقط دو شرکت قدیمی
را می‌سازد و تحت مالکیت کار فروش است؛ ابزار زیر مستقل از آن، فقط شرکت مفقود و اولین
Branding Snapshot آن را اتمیک ایجاد می‌کند. رکورد موجود، نام سفارشی، وضعیت غیرفعال،
Branding، کاربران، Permissionها و Context جاری را تغییر نمی‌دهد.

1. روی Worktree تمیز با قرارداد چهارشرکتی، `pnpm install --frozen-lockfile` را اجرا کنید.
2. متغیرهای محلی API را در `apps/api/.env` یا مسیر `RUBI_API_ENV_FILE` تنظیم کنید؛ فایل
   Secret نباید وارد Git شود. `DATABASE_URL` فقط PostgreSQL روی loopback را می‌پذیرد.
3. بسته‌های موجود را بسازید:

```powershell
pnpm --filter @rubi/contracts build
pnpm --filter @rubi/database db:generate
pnpm --filter @rubi/database build
node apps/api/scripts/local-legal-entities.mjs --check
```

4. پیش از Apply، Backup واقعی همان دیتابیس را بگیرید و در محل خصوصی ذخیره کنید. مطمئن
   شوید Task دیگری مالک عملیاتی آن دیتابیس نیست و API اجرایی از قرارداد چهارشرکتی
   پشتیبانی می‌کند. ابزار وضعیت غیرفعال را حفظ می‌کند؛ فعال‌سازی مجدد فقط در مدیریت
   مجوزدار شرکت‌ها انجام می‌شود.
5. شناسه UUID اپراتور موجود و فعال محلی را از مدیریت کاربران بگیرید و Apply را اجرا کنید:

```powershell
node apps/api/scripts/local-legal-entities.mjs --apply --actor-id=EXISTING_OPERATOR_UUID --backup=ABSOLUTE_BACKUP_PATH
node apps/api/scripts/local-legal-entities.mjs --check
```

آرگومان‌های UUID و مسیر بالا Placeholder هستند و باید با مقادیر محلی جایگزین شوند.
نبود `--apply` همیشه حالت خواندنی است. ابزار اتصال غیرمحلی و محیط production را رد
می‌کند و هیچ URL اتصال یا Credential را چاپ نمی‌کند. اجرای مجدد شرکت تکراری نمی‌سازد.
ایجاد هم‌زمان متعارض باعث rollback تراکنش می‌شود و پس از بررسی قابل تکرار است.

برای Web، `NEXT_PUBLIC_API_BASE_URL` را **پیش از build** به API همان محیط تنظیم کنید.
کاربران برای مشاهده و انتخاب شرکت‌ها از مجوزهای عمومی موجود `legal-entity.read` و
`legal-entity.switch` استفاده می‌کنند؛ نام کامپیوتر در مجوزهای کاربر نقشی ندارد.
