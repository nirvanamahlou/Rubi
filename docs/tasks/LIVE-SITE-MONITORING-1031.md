## Usage and adapter contract

In Brands & Systems choose one site; the Live Presence card follows that exact registered system and branch. The historical date range continues to control visits and sales, not current presence. A connected source with no active browser displays real zero. Unsupported/disabled/unconfigured sources and network/permission failures never display a zero or another site's numbers.

Niyayesh opt-in: apply additive erp1031p on a disposable database first, then the authorized environment; set PRESENCE_ENABLED=true server-side, keep the existing exact CORS origins, start backend/frontend with the tracker, and use the existing site-analytics.read personal resource binding. No new role or automatically granted access is created. Default is disabled. Existing registration, OIDC, admin, checkout and page-view tracking stay independent. The local frontend build preserves the already delivered registration branch fixes and adds only inert telemetry hooks. A prior unsupported named helper export in the tour Page is removed to satisfy Next Page type checking; helper behavior is unchanged.

Public input POST /api/v1/analytics/presence: browser_id, tab_id (random16..80 alphanumeric/_/-), sequence (strict safe integer), section (known fixed identifier), active (boolean). Unknown keys rejected. Trusted exact Origin + application/json required; no authenticated session/cookies sent. Browser active heartbeat20s, visible last-interacted-tab lease45s, server expiry75s; an expired/hidden tab contributes no live presence. Physical watermark cleanup removes records older than5min, periodically every60s, so bounded retention is approximately6min. A10000-browser capacity guard fails closed for new IDs; telemetry is an approximate operational signal, not an identity, anti-bot, billing or conversion authority.

Signed GET /api/v1/integration/presence uses the existing authenticated integration transport, replay checks and personal catalogue/site-analytics scope. Response nodes contain id/title/kind/column/row/count; edges contain from/to; UI validates version, site binding, bounds, edges and sum. Nora adds registrySystemId from its validated server config. Future sites implement the same versioned aggregate capability or an adapter and their actual route taxonomy. Never forward authentication cookies/credentials or reuse one site's totals for another.

Flow arrows represent possible native navigation. No individual paths, customer identifiers or inferred successful payments are shown. DNT/GPC, blocked storage/network and background pages can reduce observed coverage. Same browser counts once; different devices/profiles are different browsers. Public telemetry is not fraud-proof and production rollout still needs environment-specific capacity and edge-rate-limit review.
