# MANIFEST-TEMPLATE-PER-TICKET-0915

در انتشار بلیط Tour Workspace، کاربر از قالب‌های فعال اطلاعات پایه قالب منیفست را انتخاب می‌کند یا خروجی ساده را برمی‌گزیند. Ticket Catalog ایرلاین، مقصد، تاریخ اعتبار و مرجع فایل XLSX را با API عمومی Master Data اعتبارسنجی می‌کند، سپس شناسه و نام/نسخه/مرجع فایل را روی بلیط snapshot می‌کند. انتخاب روی تکرار بلیط نیز منتقل می‌شود؛ کلید idempotency همان انتخاب را پس از غیرفعال شدن قالب بازپخش می‌کند.

صفحه MANIFEST رزرواسیون کارت‌های بلیط در بازه را نمایش می‌دهد و برای بلیط دارای قالب، همان فایل نسخهٔ ذخیره‌شده را با اطلاعات مسافر پر می‌کند. قالب ازمیر ستون CLASS دارد و اسپارتا ندارد. بلیط بدون قالب یک XLSX ساده از اطلاعات موجود مسافر می‌دهد. محدودیت دسترسی شعبه و شرط تأیید تحویل مدارک محفوظ است.

دو فایل آمادهٔ «قالب ازمیر» و «قالب اسپارتا» در فرم اطلاعات پایه انتخاب می‌شوند. هر دو از نمونه‌های کاربر ساخته شدند اما جدول مسافرشان پاک و ماکرو حذف شده است. ایجاد/انتشار رکورد قالب نیازمند بررسی ایرلاین و شهر مقصد و ذخیره فایل در Documents است. قالب بدون مصرف قابل حذف است؛ اگر به بلیط متصل باشد، FK restrictive حذف را منع می‌کند و عمل حذف در UI به غیرفعال‌سازی برای بلیط‌های جدید تبدیل می‌شود. جایگزینی فایل قالب، مرجع قبلی Documents را آرشیو نمی‌کند تا خروجی بلیط‌های قبلی باقی بماند.

Migration `20260915110000_ticket_offer_manifest_template` چهار ستون اختیاری، index و FK افزایشی می‌سازد و داده‌های قبلی را backfill نمی‌کند. Migration در این شاخه روی DB اجرایی اعمال نشده است. ۱۲ تست مستقیم API و ۱۳ تست مستقیم Web، Prisma validate/generate، lint، typecheck و build کامل ۴۶ مسیر وب موفق‌اند.

محدودیت مسیر فعلی: تب اصلی «تعریف بلیط قابل فروش» در Ticket Workspace هنوز Preview محلی ذخیره‌شده در مرورگر است و به `TicketPublishedOffer` وصل نیست. انتخاب قالب و خروجی قرارداد در همین تحویل برای انتشار واقعی بلیط در Tour Workspace کار می‌کند؛ Preview محلی تا اتصال مستقل خود به API مالک، منیفست قراردادی تولید نمی‌کند. این اختلاف از قبل موجود بوده و با دادهٔ ساختگی پنهان نشده است.
