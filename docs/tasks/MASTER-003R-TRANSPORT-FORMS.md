## Scope and compatibility

Screenshots 439–445: airline, aircraft type, baggage rule, rail company, train type, bus company, bus type. Existing editable bilingual names, country/organization references and type/model fields are retained. Internal codes and version/audit are generated/read-only. No mockup samples are seeded.

Add optional `transportStatus` (ACTIVE/INACTIVE/UNDER_REVIEW) to the seven resources; status mutation requires `master_data.status.manage` and shares the record transaction/version/audit. Omitted PATCH fields retain prior values. Existing active/inactive API remains compatible; UNDER_REVIEW is inactive to legacy readers/selectors. A legacy explicit status change resolves the review flag.

Train facilities become a real many-to-many relation to the existing Facility catalog. Legacy `amenities` remain readable and are never erased by migration; they are displayed separately until the user selects catalog references. Bus facilities already use the same catalog. No fixed checkbox columns.

## Field inventory

| Form | Editable reference fields |
| --- | --- |
| Airlines | IATA, ICAO, Persian/English names, country, AIRLINE organization, status |
| Aircraft types | Persian/English names, manufacturer, model, body type, status |
| Baggage rules | Title, airline, flight class, ADT/CHD/INF, route scope, positive Decimal allowance (two decimal places), KG/PC, pieces, validity dates, status |
| Rail companies | Persian/English names, country, RAIL_OPERATOR organization, status |
| Train types | Persian/English names, manufacturer, model, train category, multiple catalog facilities, status |
| Bus companies | Persian/English names, country, canonical BUS_PROVIDER organization or supplier reference, status |
| Bus types | Persian/English names, manufacturer, model, service class, multiple catalog facilities, status |

The airline IATA code remains editable. Other internal reference codes are generated by the existing service (not duplicated model fields). Version and last-change time are read-only in the form. Profiles remain dialogs with an actual, paginated audit timeline. Audit access is enforced by the existing audit permission; no fabricated names or events are rendered.

Review status is filtered on the server before pagination and honored by Excel export. Clearing the optional status selector omits it from the payload; an unchanged edit status also stays out of the payload so ordinary editors need not acquire status-management permission. Mandatory selections cannot be saved empty. Train facility clearing only removes selected links, not Facility records or legacy amenities.

Baggage PATCH preserves omitted validity, rejects an invalid interval, and requires pieces for PC. Validation rejects excessive Decimal precision, out-of-range amount/piece values, invalid enum values and empty required transport fields. No capacity, price, fare, credential or financial limit is added to the transport models.
