## نتیجه

- تب، فهرست، KPI و فیلتر مستقل «نوع اتاق» از بخش اقامت حذف شد.
- کارت اقامت در صفحه اطلاعات پایه دیگر «نوع‌های اتاق» را به‌عنوان زیرسکشن نشان نمی‌دهد.
- فرم هتل یک ورودی مستقیم برای نوشتن نام نوع اتاق دارد؛ نام جدید بدون بازشدن فرم دوم ایجاد می‌شود و چند نوع اتاق را می‌توان برای هر هتل انتخاب و ذخیره کرد.
- تعریف UI نوع اتاق به یک فیلد «نوع اتاق» محدود شد و عنوان فارسی، ظرفیت استاندارد و توضیح استفاده از جریان ایجاد حذف شدند.
- `room-types` در Backend و Public Boundary به‌عنوان مرجع داخلی باقی ماند تا مصرف‌کننده‌های Sales و Reservations و داده‌های قبلی سازگار بمانند.

## خارج از محدوده

- Schema و Migration
- قرارداد عمومی و Dependency/Lockfile
- تغییر داده عملیاتی یا اجرای Migration روی دیتابیس
- تغییر مستقیم فایل‌های Sales و Reservations متعلق به PC-A
