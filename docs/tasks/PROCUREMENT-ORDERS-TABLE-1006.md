# Purchase order table and consolidated form — 2026-10-06

PC-B owns the Procurement producer and consumer. The current user authorizes the new order table/forms, removal of request-detail lifecycle tabs, push and develop merge. No shared schema, dependency, IAM grant or other-module implementation changes.

- Additive authenticated `GET /procurement/orders` returns actual orders, current version lines and request title, with request read scope (branch/own/unit), bounded search/status/date filters and stable 50-row pagination. Cancelled orders are hidden by default and remain queryable by explicit status.
- Additive `ORDER_FORM` command uses the existing request version/idempotency transaction. It requires order-manage, quote-manage and quote-select permissions, runs QUOTE → SELECT_QUOTE → ORDER atomically, and preserves minimum quotations, single-source permission/reason, current approved request version, supplier/currency validity, allocation limits, clean authorized document versions and independent final order approval. Failure rolls back every nested write. Nothing is automatically issued or sent externally.
- New-order dialog selects approved/sourcing requests and active suppliers. It captures quoted line prices/quantities, currency, warranty, delivery date/location, payment terms, tracking and Documents uploads. Price-validity and sourcing reason remain necessary controls, shown in the same form.
- Order table has full request titles, authenticated supplier logo/name, amount/currency, delivery date, status and named icon-only view/edit/cancel/discrepancy/return controls. Preview shows saved values and exact document/version links; approved orders retain the explicit permission-guarded issuance action in preview.
- Amendment now accepts pending/approved/issued unfulfilled orders, retains supplier/currency/quantity/document-reference immutability and existing receipt/invoice guards, records a new version and requests independent approval again. Replaced pending approval steps are cancelled; unrelated active order approval blocks the amendment transaction. Historical decisions/snapshots remain.
- Trash uses audited reasoned CANCEL_ORDER, preserving history and blocking orders with receipt/acceptance/invoice or unresolved discrepancies. Cancelling an order in pending final approval retires its pending steps and restores sourcing. This is not a physical database deletion.
- Order-bound discrepancy includes type, description and UTC occurrence date. Return chooses receipt lines only from that order and includes quantity, reason, date and accepted/rejected origin; backend rejects mismatched order context and preserves quantity/financial correction rules.
- Remove the lower lifecycle/records/operations panel entirely from request detail. Operational section forms and the order table remain available.

No operational writes, payment or external dispatch occurred.
