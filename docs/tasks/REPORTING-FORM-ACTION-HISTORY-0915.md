# تاریخچهٔ اقدامات فرم پیکربندی گزارش

در تب «اجراها»، نوع اقدام صریح کاربر از فرم پیکربندی گزارش نمایش داده می‌شود: «نمایش نتیجه»، «ذخیره گزارش» و «خروجی گرفتن نتیجه». نام گزارش، اجراکننده، زمان اقدام و وضعیت همان رخداد از سرور خوانده می‌شوند. خطای دریافت نتیجه یا تولید خروجی، رخداد را به وضعیت ناموفق تبدیل می‌کند.

`POST /api/v1/reports/:code/preview-run` فقط برای دکمهٔ «نمایش نتیجه» استفاده می‌شود. `POST /api/v1/reports/:code/preview` همچنان برای خواندن داده بدون ثبت رخداد (مانند صفحه‌بندی یا مرتب‌سازی) باقی می‌ماند. `POST /api/v1/reports/saved` با `recordAction: true` صرفاً ذخیرهٔ صریح فرم را هم‌زمان با Saved Report ثبت می‌کند. خروجی در مسیر موجود ایجاد خروجی ثبت می‌شود. `GET /api/v1/reports/runs` مقدار `actionType` و عنوان کاتالوگی گزارش را در پاسخ می‌دهد؛ رکوردهای پیشین بدون نوع اقدام با برچسب «اجرای پیشین» دیده می‌شوند.

نوع اقدام در `reporting_runs.filterSnapshot` نگهداری می‌شود و برای این تغییر migration لازم نیست. Scope شرکت/شعبه و Permission همچنان سمت سرور اعمال می‌شود. تنها ۱۰۰ رخداد اخیر کاربر از مسیر Runs فعلی خوانده می‌شود. دادهٔ دمو یا فایل خروجی در Git قرار نمی‌گیرد.
