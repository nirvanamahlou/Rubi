# بازکردن فرم پیکربندی از صفحات عملیاتی Reports

## مسئله

ردیف‌های «گزارش‌های من»، «اشتراک‌گذاری‌شده با من»، «اجراها» و «زمان‌بندی‌ها» کد
گزارش و Filter Snapshot را به Deep Link کاتالوگ منتقل می‌کردند، اما App Router در
تغییر Query همان نمونه `ReportingWorkspace` را نگه می‌داشت. چون مقدارهای اولیه
`useState` فقط هنگام mount خوانده می‌شوند، کاتالوگ باز می‌شد ولی فرم پیکربندی و
فیلترهای ردیف انتخاب‌شده اعمال نمی‌شدند.

## پیاده‌سازی

- یک کلید canonical و پایدار از View، گزارش، تاریخ، شرکت، ارز و فیلترهای مرتب‌شده
  ساخته شد.
- Route صفحه Reports این کلید را روی `ReportingWorkspace` قرار می‌دهد؛ بنابراین
  حرکت از جدول عملیاتی به Deep Link گزارش، Workspace را با state جدید remount می‌کند.
- فرم پیکربندی در بارگذاری جدید باز است و گزارش متناظر، تاریخ از/تا، شرکت، ارز و
  فیلترهای قابل ذخیره از URL بازیابی می‌شوند.
- فیلترهای هویت‌دار که عمداً در URL قرار نمی‌گیرند، از Session Storage همان گزارش
  بازیابی می‌شوند.
- لینک عملیات با `scroll={false}` از پرش غیرضروری صفحه جلوگیری می‌کند.

## پوشش چهار نما

- گزارش‌های من و اشتراک‌گذاری‌شده: `filterState` ذخیره‌شده گزارش.
- اجراها: `filterSnapshot` ثبت‌شده در زمان اجرا، با تبدیل بازه UTC به تاریخ محلی.
- زمان‌بندی‌ها: `savedFilterState` گزارش مبنای زمان‌بندی.

## مرز تغییر

API، پایگاه داده، Migration، Seed، مجوزها و داده عملیاتی تغییر نکردند. کنترل دسترسی
و Scope در اجرای بعدی همچنان سمت سرور ارزیابی می‌شوند؛ بازیابی UI مجوز جدیدی ایجاد
نمی‌کند.

## کنترل کیفیت

- ۳۶ تست هدفمند مدل navigation، کاتالوگ، client و Workspace موفق شدند.
- lint فایل‌های تغییرکرده و typecheck وب بدون خطا پایان یافت.
- build تولیدی Web با ۴۶ مسیر موفق شد.
