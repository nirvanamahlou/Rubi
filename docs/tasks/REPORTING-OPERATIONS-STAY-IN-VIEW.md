# REPORTING-OPERATIONS-STAY-IN-VIEW

تاریخ: 2026-09-13

مجری: PC-C

## درخواست

فرم پیکربندی گزارش هنگام انتخاب «اجرا» یا «اجرای دستی» از نماهای عملیاتی باید
بدون انتقال به کاتالوگ باز شود و زمینه فعلی کاربر را حفظ کند.

## پیاده‌سازی

- آدرس پیکربندی از همان `view` و زیرنمای فعال ساخته می‌شود؛ پارامتر گزارش و
  Filter Snapshot به URL فعلی افزوده می‌شوند و `view=catalog` دیگر تزریق نمی‌شود.
- Dialog پیکربندی از شرط رندر کاتالوگ خارج شد و برای همه نماها در سطح Workspace
  در دسترس است. جدول عملیاتی همان نما پشت Dialog باقی می‌ماند.
- کلید Workspace همچنان از View، گزارش و فیلترها ساخته می‌شود؛ بنابراین انتخاب
  ردیف دیگر فرم را با Snapshot همان ردیف باز می‌کند.
- بستن فرم، کاربر را در همان «گزارش‌های من»، «اشتراک‌گذاری‌شده با من»، «اجراها»
  یا «زمان‌بندی‌ها» نگه می‌دارد. زیرنمای «محبوب‌ها» نیز حفظ می‌شود.
- رفتار دانلود و تلاش مجدد خروجی‌های آماده/ناموفق تغییر نکرد.

## اعتبارسنجی

- 15 آزمون هدفمند Navigation و Catalog موفق.
- TypeScript وب موفق.
- ESLint فایل‌های متاثر موفق.
- `git diff --check` بدون خطا.
- Production Build در Compile و TypeScript موفق است، اما prerender دو مسیر
  نامرتبط `/_global-error` و `/pricing-management` با خطای داخلی Next.js درباره
  `workStore` متوقف می‌شود؛ فایل‌های آن مسیرها در این Task تغییر نکرده‌اند.
- هیچ API، Schema/Migration، Seed/Data، قرارداد یا Dependency تغییر نکرد.

## محدودیت محیط

Workspace فعلی Reports روی شاخه بازیابی‌شده قرار دارد و `origin/develop` جدید
این فایل‌ها را حذف کرده است. برای جلوگیری از بازنویسی کار همکاران، Merge یا
تغییر Runtime مشترک در این واحد انجام نشد.
