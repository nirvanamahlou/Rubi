قابل اجرا نمایش داده می‌شوند. اتصال HR در API به معنی بازگرداندن خودکار آن به
کاتالوگ عمومی نیست.

محدودشدهٔ migration را دور نمی‌زند. شناسه، نام مشتری/مسافر، حساب، فایل واقعی،

## معماری، امنیت و استفاده

خواندن جداول در leaf عمومی ماژول مالک انجام می‌شود؛ Reporting فقط این قرارداد
داخلی را مصرف می‌کند. مجوز Reporting، دسترسی Sales/Reservations/Ticket/Customer/HR/
Documents را جایگزین نمی‌کند. own/branch/all قرارداد، شعب مجاز و محدودیت اسناد
سمت Backend اعمال می‌شود. اجازهٔ عمومی HR یا فایل‌های دیگران اضافه نشده است.

نتیجهٔ جدید `dataLayout=SOURCE_COLUMNS` و `chartMeasure` دارد. ستون‌های منبع،
مقادیر، واحد، grain و هشدارها یک‌بار ساخته و برای preview/chart/export مصرف می‌شوند.
جدول همچنان پنج ردیف در صفحه، وسط‌چین و با فلش مرتب‌سازی برای همهٔ ستون‌هاست.
مرتب‌سازی Decimal پیش از pagination اعمال می‌شود؛ خروجی همهٔ ردیف‌های مجاز را با
همان ستون‌ها و مرتب‌سازی انتخابی می‌گیرد. گزارش پولیِ چندارزی جمع کل ساختگی ندارد.
محدودیت۱۰هزار رکورد منبع با خطا و درخواست محدودکردن بازه اعمال می‌شود، نه truncation.
سطر زمان صدور قبل از ورود پرونده و خرید گروهی با جایگزینی جزئی مبهم، خطای تطبیق‌اند.

هیچ مسیر جدید HTTP لازم نیست. مسیرهای موجود برای کدهای بالا استفاده می‌شوند:

- `GET /api/v1/reports/catalog`
- `POST /api/v1/reports/:code/preview` و `preview-run`
- مسیرهای موجود ذخیره، اشتراک، ایجاد خروجی، وضعیت و دانلود
- `/reports?view=catalog&report=<code>`

برای تأیید دوبارهٔ candidate، `scripts/reporting/readiness-audit.ts` را با همان
روش bundle و اجرای جداگانهٔ ممیزی قبلی اجرا کنید؛ این اسکریپت فقط خواندنی است،
ApplicationContext/worker راه‌اندازی نمی‌کند، هویت مرورگری نمی‌سازد و مبلغ/PII چاپ
نمی‌کند. نتیجهٔ Excel فقط در حافظه اعتبارسنجی می‌شود. فایل receipt محلی ignored
و خارج از Repository نگه‌داری شده است.

## اعتبارسنجی و انتشار

تست‌های هدفمند API شامل دسترسی، نسخه، خرید گروهی، هویت مشتری، HR self/team،
محرمانگی سند، ظرفیت، نرخ جاری، scope خروجی، precision، pagination و parity فایل است.
تست Web ستون‌های کامل، فلش‌ها، مقدار نمودار و انتقال مرتب‌سازی را بررسی می‌کند.
بررسی کامل ترجمهٔ انگلیسی و قالب B Nazanin موجود نیز حفظ شده است.

lint/typecheck/build بخش‌های متأثر و تمامی بررسی‌های hosted روی آخرین commit باید
پیش از merge موفق باشند. PR مقصد develop است؛ انتشار عملیاتی، migration پروژه،
تأیید مرورگری و تغییر نسخهٔ سرور در این واحد انجام نمی‌شود.
