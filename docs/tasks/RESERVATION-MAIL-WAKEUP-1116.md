# کاهش انتظار صف ایمیل رزرواسیون

مالک PC-A؛ شاخه codex/pc-a-reservation-mail-wakeup-1116.

پس از ثبت موفق تراکنش فرم و outbox، TravelWorkflowService پردازشگر ایمیل را برای دور بعدی event loop بیدار می‌کند. این کار منتظر بررسی پنج‌ثانیه‌ای نمی‌ماند و درخواست HTTP را تا پایان SMTP نگه نمی‌دارد. شکست commit/rollback، ذخیره معمولی فرم یا مجوز نامعتبر نباید SMTP را بیدار کند.

بیدارسازی‌های هم‌زمان تجمیع می‌شوند؛ در زمان sweep جاری، درخواست بیدارسازی نگه داشته می‌شود و پس از آن اجرا می‌شود. ردیف‌های آماده بعدی بدون فاصله پنج‌ثانیه‌ای پردازش می‌شوند. قفل SKIP LOCKED، یک پردازش فعال، nextAttemptAt، backoff و سیاست UNKNOWN بدون تغییر باقی می‌مانند. Shutdown کار معلق را لغو می‌کند؛ حالت غیرفعال هیچ پردازشی شروع نمی‌کند. بررسی پنج‌ثانیه‌ای بازیابی حفظ می‌شود و نرخ بررسی صف خالی افزایش نمی‌یابد.

۴۸ آزمون مصنوعی صف/تراکنش/PDF/SMTP و lint محدوده موفق‌اند؛ typecheck/build و گیت‌های نهایی پیگیری می‌شوند. تست بیدارسازی سریع، تراکنش معلق و شکست commit، تجمیع صد درخواست، ادامه پس از sweep فعال، تخلیه چند ردیف، صف خالی، خاموشی و حالت غیرفعال را پوشش می‌دهد. هیچ اتصال یا ایمیل واقعی در این آزمون‌ها وجود ندارد.

ظاهر Web، قالب/نسخه‌های PDF و سابقه، API عمومی، SMTP/DNS و کلیدها تغییری ندارند. این تغییر فقط انتظار صف ERP را کم می‌کند؛ تأخیر اتصال SMTP و مشکل SPF/DKIM بیرون از آن است. انتشار محدود API باید پس از گیت‌ها با قفل استقرار، پشتیبان رمزگذاری‌شده و rollback انجام شود. قبل از هر بازراه‌اندازی، نبود QUEUED/RETRY/SENDING شرط قطعی است تا هیچ ایمیل جدیدی در این کار ارسال نشود. Web بدون تغییر می‌ماند؛ Worker به namespace جدید API متصل می‌شود.
