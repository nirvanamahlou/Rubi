# RESERVATION-TICKET-PDF-PASSENGER-0914

Sales نام ثبت‌شده مسافر را همراه شناسه، رده سنی و تخصیص خدمت در Snapshot نسخه‌دار ارسالی به Reservations قرار می‌دهد. برای درخواست‌های قدیمی که این نام در Snapshot آن‌ها جا افتاده است، نمایش و PDF بلیط نام را فقط برای Projection جاری از endpoint عمومی مسافران Reservations می‌خوانند. Snapshot و سند صادرشده قبلی بازنویسی نمی‌شود و داده ساختگی تولید نمی‌شود.

Renderer بلیط ابتدا مسیر صریح محیط را می‌پذیرد و سپس Chrome یا Edge نصب‌شده ویندوز را از مسیرهای استاندارد پیدا می‌کند. فونت نازنین در صورت وجود embed می‌شود و نبود فونت سفارشی مانع PDF نیست. ورودی HTML محلی و profile موقت ایزوله باقی می‌مانند و دسترسی شبکه Chrome همچنان بسته است.

اعتبارسنجی: ۴ تست API مربوط به ساخت درخواست فروش، ۱۸ تست Web مدل/Route/Runtime، lint و typecheck API/Web و build تولیدی هر دو برنامه موفق‌اند. ساخت واقعی یک PDF با Chrome نصب‌شده و بدون متغیر محیطی مسیر مرورگر یا فونت نیز موفق شد.
