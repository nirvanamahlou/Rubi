# SALES-PRICE-MANAGEMENT-0912

## هدف

یک ورودی مستقل «مدیریت قیمت» در گروه فروش برای مرور و ویرایش روزانه قیمت تورهای
شرکت و بلیت‌های منتشرشده داخلی، همراه با انتخاب ردیف‌ها و خروجی PNG بنر قیمت.

## مرز Phase فعلی

- قیمت فروش در مالکیت Sales باقی می‌ماند و اطلاعات محصول از قرارداد عمومی Ticket/Tour
  مصرف خواهد شد؛ Query مستقیم جدول ماژول دیگر مجاز نیست.
- API موجود قیمت روزانه، تاریخچه تغییر یا انتشار بنر ندارد. تا طراحی قرارداد نسخه‌دار،
  مجوز، Audit، optimistic version و Migration افزایشی، ذخیره عملیاتی فعال نمی‌شود.
- داده صفحه synthetic و مشخص است. اعتبارسنجی مبلغ/ارز/تاریخ واقعی و خروجی PNG واقعی
  مرورگر هستند، ولی دکمه اعمال فقط وضعیت Preview همین نشست را تغییر می‌دهد.
- هیچ نرخ ارز ضمنی، قیمت خرید، تخفیف قرارداد، ظرفیت یا موجودی ساختگی به‌عنوان داده واقعی
  سامانه منتشر نمی‌شود.

## معیار پذیرش

- ترتیب گروه فروش: قرارداد، مدیریت قیمت، مشتریان و مسافران، امور مشتریان، سازمان‌ها،
  مارکتینگ.
- فیلتر تاریخ، نوع محصول و جست‌وجو؛ ورود قیمت صحیح Decimal و IRR بدون اعشار.
- انتخاب فقط تور و بلیت ملکی برای بنر، پیش‌نمایش قابل خواندن و دانلود PNG واقعی.
- Responsive، RTL، حالت خالی/خطا و اعلان روشن عدم ذخیره عملیاتی.

## نتیجه و اعتبارسنجی

- route مستقل `/pricing-management` و ترتیب گروه فروش پیاده شد؛ UI چهار ردیف نمونه
  ملکی، KPI، فیلتر، ویرایش Preview، انتخاب بنر و سه تم خروجی دارد.
- ۲۳ تست هدفمند در پنج فایل موفق: قرارداد ناوبری، جمع‌شدن گروه‌ها، مدل قیمت روزانه،
  helper بنر و SSR workspace.
- `pnpm --filter @rubi/web typecheck`، lint محدود فایل‌های متاثر و Production Build
  با ۴۲ مسیر موفق‌اند.
- Browser روی Web3200 نمایش RTL/Responsive، وجود چهار ردیف و پیام موفقیت ساخت PNG را
  تأیید کرد؛ Console خطای مرتبط نداشت. مرورگر داخلی رویداد Download را در automation
  در معرض ابزار قرار نداد، اما اجرای canvas/Blob و مسیر موفقیت برنامه کامل شد و helper
  نام/فرمت فایل نیز تست واحد دارد.
- Commit قابلیت `c8f41fc` روی origin Push و Draft PR #161 با base
  `codex/pc-a-finance-core-accounting` ایجاد شد.
