## Private connection setup and compatibility

The existing server-only `NIYAYESH_CONNECTION_FILE` remains the primary read/write/SSO connection. Optional `reportConnections` is an array of complete independent reporting configurations with `registrySystemId`, origin, local flag, client, external system, organization, environment, keyId, secret, users and optional managedAccess. Real credentials never belong in this document, browser or Git. Each extra site must implement the existing signed report/resource v1 protocol or receive its own verified adapter; adding a registry card does not create a working external connection. No extra production sites or example credentials were configured by this change. Unknown selected IDs never fall back to the primary connection. Existing catalogue writes, workbook imports and SSO still use their original primary binding; this task expands reporting only.

A source failure is isolated to its own report result and cannot make another site appear successful. Report responses are checked against exact site/range before rendering, and results are also keyed by branch/range/current registry IDs to prevent stale async data. Visits, operational KPI, trend and activity use the same site selection. The four registry cards/comparison retain independent source values. Registry setup history is deliberately kept in registry logs instead of being rendered as external site activity. Activity navigation opens the selected site's management space.

No schema or dependency changes. Runtime uses the existing local Compose and persistent volumes; no main/develop merge or production deployment is authorized. Owner approved Docker Desktop recovery restart after Engine500 and failed stop; unrelated project containers/settings are preserved.
