# آمار و مدیریت دادهٔ سایت در نورا — PC-D — ۱۴۰۵/۰۸/۰۵

## تحویل محلی تأییدشده

نورا در http://nora.localhost:3100/integrations و نیایش در
http://niyayesh.localhost:13025/admin با تصویرهای نهایی Docker سالم‌اند. مسیر:
«برندها و سامانه‌ها ← مدیریت نیایش ← آمار، اطلاعات و ورود فایل».
هر سه تیک ورود Excel برای ehsan و مجوز متناظر حساب شخصی نیایش از API مدیریت
کاربران فعال شده‌اند. کاربران دیگر مجوز نوشتن پیش‌فرض دریافت نکرده‌اند.

شمارش فعلی دادهٔ محلی: ۲ کاربر، ۹ تور، ۶ هتل، صفر خریدار سبد باز، صفر سفارش
پرداخت‌شدهٔ لغونشده و یک سفارش منتظر پرداختِ منقضی‌نشده. دادهٔ تولید نیست.
تازه‌سازی دستی است؛ برای سایت‌های دیگر داده یا اتصال فرضی نمایش داده نمی‌شود.

build کامل Web با Webpack، بررسی TypeScript و تولید ۶۵ صفحه موفق شد؛ کنترل‌ها
غیرفعال نشده‌اند. API build/types، lint/format/i18n و تست‌های ۱۱ API/SSO، ۲۵ Web،
شش مورد workspace، ده رگرسیون بومی واردکننده و دو آزمون واقعی PostgreSQL پاس‌اند؛
مجموعهٔ کامل سایت نیز پیش از اصلاح محدود هویت هتل پاس شد. تست زندهٔ HTTP شامل
قالب‌های واقعی، خروجی شهر، پیش‌نمایش multipart از نورا با valid=true و applied=false
و بدون ساخت هتل تازه، ورود شخصی OIDC، دسترسی Excel بدون owner و لغو فوری نشست
پس از خروج از نورا موفق است. دادهٔ کسب‌وکار محلی برای آزمایش نوشته نشد؛ apply
واقعی در پایگاه‌های آزمون مجزا بررسی شد. دسترسی مرورگر در Work غیرفعال بود؛
تأیید ظاهری/کلیک تعاملی این نسخه انجام نشده است.

بستهٔ API فقط خروجی فایل‌های نیایش را روی تصویر قبلی اعمال می‌کند؛ Telephony/IAM
قبلی حفظ می‌شوند. تنظیم Compose و اسکریپت شروع قبلی به تصویرهای 1027 متصل‌اند.
همهٔ سرویس‌های دیگر Docker در پایان سالم‌اند. کد روی شاخهٔ کاری نورا و erp_panel
کامیت و پوش شده است؛ PR، مرج یا انتشار تولید انجام نشده است.

درخواست مالک: آمار واقعی هر سایت، جزئیات تور و هتل و سفارش و ورود Excel هتل،
قیمت تور و بلیت در فضای همان سایت. مقصد اجرای فعلی دو نسخهٔ محلی نورا و نیایش
است؛ main/develop نیایش تغییر نمی‌کنند. شاخهٔ نورا از PC-D-Integration با دو
پیش‌نیاز منتشرشدهٔ اتصال خواندنی و ورود شخصی ساخته شده است.

## قرارداد و مالکیت

Producer نیایش، قرارداد افزایشی niyayesh.erp.v1؛ Consumer ماژول Integrations نورا.
اطلاعات از API امضاشده با نگاشت شخصی، سازمان، سامانه و محیط می‌آید. هیچ دسترسی
مستقیم نورا به جدول سایت، کپی مشتری/فروش/رزرو در نورا یا تأیید مالی ایجاد نمی‌شود.
آمار و عملیات فقط به شناسهٔ سامانهٔ ثبت‌شده در تنظیم امن سرور متصل می‌شوند؛
نام، آدرس تایپ‌شده یا payload مرورگر مجوز انتخاب مقصد دیگری ایجاد نمی‌کند.
سایت فاقد اتصال واقعی با حالت «متصل نشده» باقی می‌ماند.

## تعریف شاخص‌ها و جزئیات

| شاخص | مبنای دقیق سایت |
| --- | --- |
| کاربران ثبت‌نام‌شده | CustomerAccount حذف‌نشده، شامل غیرفعال |
| تورها | Tour حذف‌نشده، شامل پیش‌نویس و منتشرشده |
| هتل‌ها | Hotel حذف‌نشده |
| سبدهای در حال خرید | تعداد مشتریان متمایز با حداقل یک قلم سبد cart/new و حذف‌نشده |
| فروش تأییدشده سایت | سفارش paid و لغونشده و حذف‌نشده؛ به معنی تأیید مالی ERP نیست |
| سفارش منتظر پرداخت | unpaid، لغونشده و حذف‌نشده و منقضی‌نشده؛ موعد پیش‌فرض رکورد قدیمی ۳۰ دقیقه |

GET /integration/dashboard شمارش کامل سمت سایت می‌دهد، نه تعداد صفحهٔ اول.
همهٔ شمارش‌ها زیر قفل clock موجود با snapshot سازگار خوانده می‌شوند.
نبود مجوز با value=null و FORBIDDEN نمایش داده می‌شود؛ صفر واقعی مقدار صفر دارد.
GET /integration/resources/{resource}?metric=... همان predicate شاخص را برای
جزئیات صفحه‌بندی‌شده استفاده می‌کند. جزئیات سبد، اقلام مشتریان شمارش‌شده را
نشان می‌دهد و ممکن است برای یک مشتری چند قلم داشته باشد. زمان آخرین دریافت
نمایش داده می‌شود؛ تازه‌سازی دستی است. پول جمع یا تبدیل نشده است.

## Excel با منطق بومی سایت

- قالب‌های هتل، قیمت تور و بلیت همان فایل‌های نسخهٔ سایت‌اند؛ تست برابری بایت‌ها
  مانع اختلاف بی‌خبر بین قالب‌های دو مسیر می‌شود.
- POST /integration/workbooks/{hotels|tour-prices|tickets}، JSON حاوی فایل base64؛
  مرورگر فقط multipart به API نورا می‌فرستد. credential هیچ‌گاه به مرورگر نمی‌رود.
- فایل حداکثر ۴MiB، دادهٔ بازشده حداکثر ۳۲MiB، حداکثر ۱۰۰۰ ورودی ZIP، ۱۰هزار
  ردیف، ۱۲۸ ستون و ۲۰۰هزار سلول؛ macro، external links، DTD و entity رد می‌شوند.
- preview فقط از parser و import service موجود با apply=false استفاده می‌کند.
  proof امضاشدهٔ ۱۵دقیقه‌ای به actor، بایت فایل، نام فایل، گزینه‌ها، محیط/سامانه
  و revision کل سایت بسته است. تغییر سایت یا ورودی، پیش‌نمایش مجدد لازم دارد.
- apply همان import service موجود را در transaction/clock/receipt/audit فعلی
  اجرا می‌کند. کلید ثابت عملیات با nonce تازه تکرار می‌شود؛ ثبت هم‌زمان یا retry
  به تکثیر داده نمی‌انجامد. پاسخ نامعلوم باید با همان کلید تکرار شود.
- delete_missing همیشه false است. هتل‌ها و بلیت‌های غایب از فایل حذف نمی‌شوند.
  قیمت تور طبق رفتار بومی همان تاریخ‌های واردشده را به‌روز می‌کند؛ وضعیت و
  ظرفیت حرکت را تغییر نمی‌دهد. ترکیب هتل‌ها از تنظیمات خود تور خوانده می‌شود.
- خروجی شهر با export مجاز، همان hotel city workbook موجود را بازمی‌گرداند؛
  بیش از ۲۰۰۰ هتل یا خروجی بزرگ‌تر از ۱MiB به خروجی بومی سایت ارجاع می‌شود.

## مجوزها

سه تیک مستقل در مدیریت کاربران نورا: integrations.niyayesh.import.hotels،
integrations.niyayesh.import.tour-prices و integrations.niyayesh.import.tickets.
مجوز connections و شعبه و نگاشت منبع همچنان لازم است. پیش‌نمایش نیازمند read
منبع و read واردکننده و ماژول excel سایت است؛ ثبت به create/bulk واردکننده و
update منبع، و برای هتل/بلیت create/publish منبع نیز نیاز دارد. خروجی مجوز export
جدا دارد. SSO فقط اشتراک policy سرور، تیک فعلی کاربر و منابع مجاز را صادر می‌کند.
حساب‌های جدید همچنان پیش‌فرض خواندنی‌اند. هیچ owner یا user delegation اضافه نشده.
درخواست multipart نورا header اختصاصی برای جلوگیری از form CSRF دارد.

## اعتبارسنجی و محدودیت تحویل

تست‌های شاخص و drill-down، پیش‌نمایش/ثبت هتل و قیمت تور و بلیت، تغییر فایل/proof،
انقضا، رد مجوز، محدودیت XLSX و تطابق قالب‌ها پاس شدند. PostgreSQL موقت از ابتدا
تا erp1026b مهاجرت کرد؛ سه apply هم‌زمان فقط یک هتل و یک journal ساختند و دو
پاسخ replay شدند؛ پیش‌نمایش قدیمی رد شد. تست هم‌زمانی قرارداد قبلی نیز پاس شد.
مجموعهٔ کامل سایت و تست‌های هدفمند API/Web، typecheck و lint اجرا شدند؛ نتیجهٔ
build و بررسی تعاملی محلی در گزارش تحویل نهایی ثبت می‌شود.

این کار migration یا dependency جدید ندارد. همگام‌سازی زمان‌بندی‌شده، دفتر مالی
ERP، صدور/لغو تجاری، انتقال مشتری و سایت‌های دیگر عملیاتی اعلام نمی‌شوند.
مرج، استقرار تولید یا تغییر پایگاه عملیاتی در این واحد انجام نمی‌شود.
