# TICKET-CATALOG-EDIT-COMPLETENESS

## هدف

فرم ویرایش بلیت باید تمام اطلاعات ثبت‌شده را نشان دهد؛ حتی وقتی یک رکورد قدیمی
شناسه مرجع منتشرشده ندارد و فقط Snapshot نمایشیِ ایرلاین، وسیله، مسیر یا ارز در آن
باقی مانده است.

## محدوده

- نمایش خلاصه عنوان، وضعیت، نوع مسیر و نسخه در ابتدای فرم ویرایش.
- نمایش صریح مقدار ذخیره‌شده برای ایرلاین/شرکت، نوع وسیله، شهرهای مسیر، فرودگاه‌ها
  و ارز، تا زمان انتخاب یک مرجع منتشرشده جدید.
- حفظ منطق فعلی ویرایش، وضعیت، ظرفیت، نرخ، قوانین و تاریخچه.
- بدون ایجاد مرجع ساختگی، تغییر API، Schema/Migration، Seed یا Dependency.

## معیار پذیرش

- مقدار مرجع معتبر مانند قبل با نام و کد نمایش داده می‌شود.
- اگر شناسه مرجع در رکورد قدیمی موجود نیست، Snapshot ذخیره‌شده حذف یا پنهان نمی‌شود.
- رابط روشن می‌گوید مقدار نمایش‌داده‌شده از نسخه ثبت‌شده است و برای جایگزینی باید
  مرجع جدید انتخاب شود.
- فرم ایجاد بلیت و اعتبارسنجی ذخیره بدون تغییر رفتار باقی می‌مانند.

## نتیجه و کنترل کیفیت

- تست هدفمند فرم و رندر Ticket Catalog: ۱۰ تست موفق.
- تست کامل Web: ۵۶۵ تست موفق در ۷۳ فایل.
- Web lint و typecheck کامل: موفق.
- Production Build: موفق؛ مسیر `/ticket-management` تولید شد.
- نسخه build‌شده روی `http://127.0.0.1:3100` اجرا شد. ابزار کنترل مرورگر در این
  نشست به محدودیت دسترسی Windows برخورد کرد؛ رندر فرم و محتوای Snapshot با تست
  سروری مستقل پوشش داده شد.
