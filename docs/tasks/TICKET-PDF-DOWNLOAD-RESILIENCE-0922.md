# TICKET-PDF-DOWNLOAD-RESILIENCE-0922

## مسئله

دانلود بلیط در route سمت سرور گاهی با پیام عمومی «PDF بلیط آماده نشد» متوقف می‌شد، در حالی که موتور Chrome سالم بود. دو وابستگی غیرضروری می‌توانستند کل خروجی را شکست دهند:

- لوگوی ثابت شرکت فقط از `process.cwd()/public/brand` خوانده می‌شد و اجرای یکپارچه از ریشه Repository آن را پیدا نمی‌کرد.
- خطای شبکه یا JSON نامعتبر در اطلاعات جانبی شهر به catch نهایی route می‌رسید.

## تصمیم و محدوده

- فایل برند فقط از دو مسیر ثابت و شناخته‌شدهٔ Web خوانده می‌شود و سقف ۵ مگابایت حفظ شده است.
- اطلاعات شهر enrichment اختیاری است؛ در شکست آن قالب از fallback موجود استفاده می‌کند.
- برای نبود فایل برند کد خطای پایدار و پیام مشخص کاربر تعریف شده است.
- API، قرارداد مشترک، قالب بصری بلیط، Schema/Migration، Permission و داده عملیاتی تغییر نکرده‌اند.

## بررسی

- ۱۷ تست عادی PDF موفق.
- smoke واقعی با Chrome نصب‌شده، لوگوی واقعی پروژه و خروجی معتبر `%PDF-` موفق.
- lint فایل‌های متاثر، typecheck کامل Web و build تولیدی Web با ۵۰ route موفق.
