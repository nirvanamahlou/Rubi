## حدود داده و مجوز

HR API برای HR managers اعلان‌های شعب مجاز، برای self/team دامنه مجاز کاربر و محرمانگی را روی سرور اعمال می‌کند؛ این داده «درخواست‌های تخصیص‌یافته من» نامیده نشده است. API حداکثر100اعلان آخر می‌دهد، بنابراین شمارنده UI صریحاً تعداد خوانده‌نشده همین فهرست است، نه کل درخواست‌ها یا کل تاریخچه. نتیجه HR با اعلان سیستمی ادغام/تکرار نمی‌شود. نام/پرونده فقط از پاسخ مجاز دریافت می‌شود؛ هیچ userId/branch دلخواه به API ارسال نمی‌شود.

خواندن اعلان از میزکار فقط HrNotificationRead را از سرویس عمومی تغییر می‌دهد، نه وضعیت درخواست HR. Deep link همان helper رسمی زنگ HR است. تغییر هدف/مسئول درخواست، تأیید مرخصی، سند مالی، صدور یا تخصیص در این تغییر انجام نمی‌شود.

## وابستگی‌های مسدود و اقدام لازم

آخرین remote مالی codex/pc-a-finance-core-accounting و PR153 قفل Migration/Central IAM/Sales/Travel را نزد رزرواسیون تأیید می‌کنند. دستور اصلی کاربر هنگام فعال‌بودن قفل، Schema/Migration و persistence ساختگی را منع کرده است. بنابراین سرویس عمومی Requests/Tasks/Messaging، یادداشت و ترجیحات خصوصی و stars پایدار باید پس از handoff همان مالک ساخته شوند؛ استفاده از جدول HR/Documents یا localStorage به جای آن‌ها مجاز نیست. HR notifications موجود اکنون مصرف می‌شود، اما کپی request یا پیام خصوصی به جداول HR ساخته نشده است.

فعال‌سازی API تغییر رمز مانع مستقل ابزار است؛ تأیید کاربر ثبت شده اما اجرای جایگزینی API دو بار رد شده. در این audit هیچ retry یا اجرای جایگزین برای آن اقدام انجام نشد.

## رزرو و اعتبارسنجی

فایل‌های Workbench consumer/navigation/tests و تغییر محدود notification-center.tsx به success events؛ همچنین change-notifications.ts/spec برای حذف security events از feed عمومی رزرو شد. API/schema/contracts/dependency دست‌نخورده؛ مالکیت نهایی ماژول‌ها حفظ شده است. تست‌های permission routing، عدم ارتقای مجوز از Documents، عدم اعلان موفقیت read ناموفق و استثنای رخداد امنیتی اجرا می‌شوند. Build و بررسی مرورگر قبل از تحویل ثبت خواهد شد.
