# WORKBENCH-021 — پیام‌رسان داخلی پایدار

## نتیجه

میزکار اکنون فهرست مخاطبان داخلی CRM، گفت‌وگوی مستقیم، ساخت گروه، پیام‌های
پایدار و فوروارد پیام را از سرویس واقعی Messaging دریافت می‌کند. همه عملیات با
نشست ورود انجام می‌شوند و رابط برای هر خطای API حالت شکست قابل‌مشاهده دارد.

## مرز IAM و دسترسی

- IAM فقط `id`، نام نمایشی، نام کاربری و شعب مشترک مخاطب را از projection عمومی
  Messaging برمی‌گرداند.
- فقط حساب‌های `ACTIVE` داخلی که حداقل یک شعبه فعال مشترک با کاربر دارند نمایش
  داده می‌شوند؛ حساب‌های متصل به پرتال آژانس و خود کاربر حذف می‌شوند.
- ایجاد گروه نیازمند یک شعبه مجاز مشترک میان سازنده و همه اعضا است.
- فهرست گفت‌وگو، خواندن پیام، ارسال و فوروارد فقط برای عضو گفت‌وگو و در شعبه‌ای
  که هنوز در محدوده actor است انجام می‌شود.

## قرارداد v1

- `GET /api/v1/messaging/contacts`
- `GET /api/v1/messaging/conversations`
- `POST /api/v1/messaging/conversations/direct`
- `POST /api/v1/messaging/conversations/groups`
- `GET /api/v1/messaging/conversations/:id/messages`
- `POST /api/v1/messaging/conversations/:id/messages`
- `POST /api/v1/messaging/conversations/:id/forwards`

ساخت گروه و پیام‌ها کلید درخواست پایدار دارند. فوروارد متن ذخیره‌شده پیام مبدأ
را روی سرور کپی می‌کند و فقط نام فرستنده اصلی را در مقصد نشان می‌دهد؛ عضویت یا
شرکت‌کنندگان گفت‌وگوی مبدأ افشا نمی‌شوند.

## داده و Migration

Migration افزایشی `20260912190000_workbench_messaging` سه جدول گفت‌وگو، عضویت
و پیام را با FK واقعی به User و Branch، مرجع self-FK فوروارد و uniqueهای
idempotency ایجاد می‌کند. constraint پایگاه‌داده شکل مستقیم/گروهی و متن غیرخالی
را نیز حفظ می‌کند.

- کل ۵۶ Migration روی PostgreSQL ایزوله اعمال و وجود هر سه جدول تأیید شد.
- ۱۲۲۲ تست API و ۱۳۲۷ تست Web پاس شدند.
- lint فایل‌های API/Web متاثر و typecheck هر دو برنامه پاس شدند.
- build تولیدی API و Web با ۴۶ route موفق است.

در QA مرورگر هیچ پیام یا گروه آزمایشی برای کاربران واقعی ایجاد نمی‌شود. پیوست

ارسال متن ثبت‌شده را فعال می‌کند.
