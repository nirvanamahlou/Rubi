# WORKBENCH-036 — اتصال کامل بک‌اند میزکار

## نتیجه

میزکار از حالت مجموعه‌ای از فرم‌ها و داده‌های مرورگر خارج شد و برای هر قابلیت
عملیاتی یک مالک و قرارداد بک‌اند دارد. `WorkbenchModule` فقط داده‌های شخصی
یادداشت و تقویم را مالک است و داده ماژول‌های دیگر را از سرویس عمومی همان ماژول
دریافت می‌کند.

| بخش میزکار | مالک بک‌اند | ارتباط اجراشده |
| --- | --- | --- |
| خانه و اعلان‌ها | Notifications / HR | اعلان‌های شخصی با وضعیت خوانده‌شدن و پنج اعلان آخر HR از APIهای مالک دریافت می‌شوند. |
| درخواست جدید و کارتابل | Customer Affairs / HR | درخواست پایدار با شعبه، واحد مقصد و کارشناس پاسخ‌گو ثبت می‌شود؛ HR کاربر فعال واحد را resolve و Notifications گیرندگان را مطلع می‌کند. |
| پیام‌رسان | Messaging / IAM / Documents / Notifications | مخاطبان فعال CRM از IAM، گفت‌وگوی مستقیم و گروهی و فوروارد سروری از Messaging، پیوست از Documents و اعلان پیام برای اعضای دیگر ثبت می‌شود. |
| فایل‌ها و ستاره‌دارها | Documents | بارگذاری‌ها در آرشیو Documents می‌مانند و علاقه‌مندی کاربر با FK واقعی و API مشترک در هر دو صفحه همگام است. |
| یادداشت‌ها | Workbench / IAM Audit | پوشه، متن، چک‌لیست، سنجاق، یادآور و نسخه در دیتابیس ذخیره می‌شوند و تغییرات در Audit حساب ثبت می‌شود. |
| تقویم | Workbench / Customer Affairs / Documents | رویداد شخصی با متن، لینک و تصویر ذخیره می‌شود؛ `GET /workbench/calendar` ارجاع‌های مجاز Customer Affairs را در خود بک‌اند تجمیع می‌کند. |
| نظرسنجی | Workbench Feedback / HR / Documents / Notifications | نظرسنجی پایدار و idempotent، مقصد واحد، پیوست و اعلان تراکنشی دارد؛ projection گیرنده در حالت ناشناس هویت فرستنده را حذف می‌کند. |
| پروفایل و امنیت | IAM / Documents | نام، ایمیل، تلفن و مرجع عکس در سرویس عمومی IAM و یک تراکنش Auditدار ویرایش می‌شوند؛ عکس ابتدا توسط Documents و مرجع مالک/شعبه اعتبارسنجی می‌شود. |
| فعالیت‌های من | IAM Audit | عملیات موفق حساب از Audit مرکزی و با دامنه همان کاربر برگردانده می‌شود. |

## API و مرزها

- مسیرهای شخصی میزکار زیر `/api/v1/workbench` شامل notes، note-folders،
  calendar، profile و activity هستند و همگی نشست معتبر می‌خواهند.
- پیام‌رسان زیر `/api/v1/messaging` عضویت و شعبه را در هر خواندن/نوشتن کنترل
  می‌کند. فوروارد، متن و پیوست پیام مبدأ را فقط پس از اثبات عضویت از نسخه سرور
  کپی می‌کند.
- Favorites زیر `/api/v1/documents/favorites` فقط اسنادی را برمی‌گرداند که
  کاربر هنوز مجوز مشاهده آن‌ها را دارد.
- درخواست‌های ساخته‌شده از میزکار زیر
  `/api/v1/customer-affairs/workbench/requests` با creator و شعبه محدود می‌شوند.
- Workbench هیچ جدول Customer Affairs، HR، Documents، Notifications یا
  Messaging را مستقیم نمی‌خواند؛ orchestration از public service انجام می‌شود.

## مدل داده و سازگاری

Migration افزایشی `20260912200000_workbench_integrations` پوشه/یادداشت، رویداد
تقویم، پروفایل تکمیلی IAM، علاقه‌مندی سند، پیوست پیام و زمان آخرین خواندن عضو را
اضافه می‌کند. همه ارتباط‌ها FK واقعی دارند، حذف سند پیوست‌شده محدود است و
یادداشت/تقویم optimistic version دارند. قراردادهای v1 فقط به‌صورت افزایشی گسترش
یافته‌اند و مصرف‌کنندگان قبلی همچنان معتبرند.

## کنترل کیفیت

- ۲۴ تست هدفمند API برای Workbench، IAM Profile، Documents، Messaging، Customer
  Affairs و Feedback پاس شد.
- ۴۷ تست Workbench Web و ۱۰ تست مرز HTTP اسناد پاس شد.
- lint سراسری با ۶ Job، typecheck سراسری با ۹ Job و build تولیدی با ۶ Job و ۴۶
  مسیر Web پاس شد.
- Prisma format، generate و validate پاس شد. تمرین کامل تاریخچه روی دیتابیس
  موقت محلی به‌دلیل پاسخ‌ندادن Docker Desktop در Migration سوم متوقف شد؛ SQL
  همین Migration، schema و کل تاریخچه در CI روی PostgreSQL موقت دوباره اجرا
  می‌شوند و Merge فقط پس از عبور Gateهای Repository انجام می‌شود.

هیچ پیام، گروه، درخواست، نظرسنجی یا فایل ساختگی برای کاربران واقعی ایجاد نشد و
هیچ داده عملیاتی در بررسی این تغییر دست‌کاری نشد.
